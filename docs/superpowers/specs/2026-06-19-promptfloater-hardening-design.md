# PromptFloater 稳健升级设计

## 目标

在不改变现有视觉与主要交互的前提下，解决数据丢失、恶意导入、HTML 注入、静默失败、用户数据目录不规范和启动环境污染问题，并建立可重复执行的自动化测试。

## 范围

本轮包含：

- 数据结构校验与版本标识。
- 原子保存、自动备份与损坏恢复。
- 项目数据到系统用户数据目录的一次性迁移。
- 前端安全渲染与保存结果反馈。
- 可轮转的本地日志和用户可读错误。
- Windows、macOS 启动脚本的虚拟环境隔离。
- Python 数据层测试与前端安全回归测试。

本轮不包含：

- UI 改版。
- 云同步、账号、加密或多人协作。
- 自动更新。
- Windows/macOS 安装包、签名与公证。

## 架构

### 应用入口

`app.py` 只负责单实例、窗口生命周期、屏幕与窗口控制、剪贴板，以及向 WebView 暴露经过约束的应用服务。数据读写、校验和迁移不再作为 `main()` 内部函数存在。

### 数据模型与服务

新增独立 Python 模块，负责：

- 校验根对象、分类和提示词条目的字段与类型。
- 要求分类 ID 和提示词 ID 在各自作用域内唯一。
- 标准化可选字段 `desc` 与 `fav`。
- 给数据增加显式 `schema_version`。
- 限制分类数量、条目数量和文本长度，防止异常导入耗尽内存。

数据服务公开清晰接口：加载、保存、验证导入和定位数据目录。前端不能指定任意文件路径。

### 持久化

用户数据目录使用：

- Windows：`%APPDATA%\PromptFloater`
- macOS：`~/Library/Application Support/PromptFloater`
- 其他平台：`~/.local/share/PromptFloater`

首次运行时，如果用户目录尚无数据而项目 `data/prompts.json` 存在，则校验后复制为初始数据。项目内文件随后只作为随应用分发的默认数据，不再承载用户修改。

保存流程：

1. 在内存中完成完整校验与标准化。
2. 写入同目录临时文件并刷新到磁盘。
3. 将当前有效文件保存为单份 `.bak`。
4. 原子替换正式文件。
5. 返回结构化成功或失败结果。

加载正式文件失败时尝试备份；备份也失败时加载随应用分发的默认数据，并记录错误。任何恢复都不得覆盖损坏文件，避免丢失取证信息。

## 前端安全与数据流

分类、提示词、描述和导入数据均视为不可信输入。动态列表使用 `document.createElement`、`textContent`、`dataset` 和事件监听器构建，不把用户数据拼接到 `innerHTML`。

导入流程：

1. 浏览器读取 JSON 文本并完成基本解析。
2. 将对象交给后端 `validate_import`。
3. 后端返回标准化数据或具体校验错误。
4. 用户确认保存后调用 `save_data`。
5. 只有后端确认写入成功，前端才替换当前状态并显示成功提示。

普通新增、编辑、删除、收藏和分类操作也等待后端保存结果。失败时保留编辑内容、恢复内存中的旧状态并显示错误，不再依赖 `localStorage` 作为第二个相互竞争的数据源。

复制逻辑在系统剪贴板失败后正确进入浏览器降级路径，异步拒绝也必须被捕获。

## 错误处理与日志

- 移除裸 `except:`，只捕获预期异常或记录完整异常信息。
- 日志写入用户数据目录下 `logs/promptfloater.log`。
- 使用滚动日志，单文件最大 1 MB，保留 3 份。
- 对用户显示简短中文错误，对日志记录技术细节。
- 正常退出使用 WebView 生命周期关闭，不使用 `os._exit(0)` 强制终止。

## 启动脚本

Windows 和 macOS 启动脚本优先使用项目 `.venv`。不存在时创建虚拟环境，并通过该环境的 `python -m pip` 安装依赖，禁止调用不确定归属的全局 `pip`。

依赖采用兼容范围上限，避免未来主版本变化造成不可重复安装；保留面向开发者的 `requirements.txt`。

## 测试策略

Python 测试覆盖：

- 有效数据的校验与标准化。
- 缺失字段、错误类型、重复 ID、超限数据和恶意字符串。
- 原子保存成功、保存失败不破坏旧文件。
- 正式文件损坏后的备份恢复。
- 首次运行数据迁移。
- 各平台用户数据目录选择。

前端回归检查覆盖：

- 动态渲染不使用用户数据拼接 `innerHTML`。
- 保存失败不提交新状态且显示失败反馈。
- 导入必须经过后端验证。
- 剪贴板异步失败进入降级路径。

集成验证包含 Python 编译、JSON 校验、JavaScript 语法检查、依赖一致性检查和受控桌面启动烟测。

## 验收标准

- 现有 7 个分类和 56 条提示词可无损迁移。
- 搜索、新建、编辑、删除、收藏、分类、导入、导出、复制、贴边和退出行为保持可用。
- 任意无效导入不会覆盖现有数据。
- 保存中断不会破坏上一版有效数据。
- 用户数据不再写入源码目录。
- 用户输入无法通过动态列表渲染注入 HTML 属性或事件。
- 自动化测试和启动烟测全部通过。
